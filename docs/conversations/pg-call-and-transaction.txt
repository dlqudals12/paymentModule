AI:
`transactionTemplate`을 쓴 이유는 **PG 통신 중에 DB 트랜잭션과 결제 행 잠금을 유지하지 않기 위해서**입니다.

현재 `PaymentService.payment()`는 다음 순서입니다.

1. 짧은 트랜잭션에서 결제를 잠그고 `PROCESSING`으로 저장
2. 트랜잭션 밖에서 PG 승인 API 호출
3. 새 트랜잭션에서 승인 결과, `payment_history`, `payment_api_log` 저장

메서드 전체에 `@Transactional`을 붙이면 PG 응답을 기다리는 동안 잠금이 유지됩니다. `transactionTemplate`은 한 서비스 안에서 이 경계를 명시하려고 선택한 방식입니다. 별도 트랜잭션 서비스로 분리해 `@Transactional`을 적용하는 것도 가능합니다.

다만 **PG 승인과 DB 저장은 하나의 트랜잭션이 될 수 없어서**, 승인 후 DB 저장이 실패한 경우에는 결제 조회로 결과를 확인하는 복구 처리가 필요합니다.
